# 设计规范

这是一份可执行的规范：每一条都对应代码里的一个 token、一个组件或一条规则，改动前先改这里。
配套文件是 `app/globals.css`（token 与 Tailwind 主题）和 `components/ui/`（组件层）。

---

## 1. 这个界面是什么

一个**游戏台**：一张**游戏导航首页**，加上每个游戏一台**机台**。机台的左侧是游戏本身，
右侧是模型在这个游戏里做决策的全部证据。两条主线贯穿每个游戏页面，
任何不属于这两条线的信息都不占用版面：

| 主题 | 位置 | 回答的问题 |
| --- | --- | --- |
| **游戏画面与游戏参数** | 左栏 | 现在场上发生了什么，这一局的成绩如何 |
| **模型决策可视化** | 右栏 | 它看到了什么、选了哪个动作、有多确定、值不值得信 |

**右栏的构成对所有游戏都一样**（决策卡 → 整局置信度 → 历史 / 指标 / 状态三个标签页），
它就是「模型怎么决策」这件事的展示基准；游戏之间的差异被压缩到**左栏、动作词表与自身色**三处。
因此右栏的每条规则都是全局规则，加游戏时不需要重新讨论。

设计基调沿用原有的 Linear 系暗色数据工具语汇：近黑画布、按亮度分层的表面、发丝级半透明描边、
**只有一个彩色界面强调色**（靛蓝）。游戏配色（吃豆人琥珀、迷宫蓝、四只幽灵、蛇的绿）是**数据**，
只出现在画布和表示「该游戏主体」的数值上，绝不用于界面装饰。

## 2. 布局规范

### 2.1 单屏应用壳

页面本身**不滚动**。整页锁定 `100dvh`，只有面板内部滚动。

```
┌──────────────────────────────────────────────────────────────┐
│ header  52px   品牌 · 状态 · 种子 · 时长 · 主操作(开始/暂停)      │
├───────────────────────────────┬──────────────────────────────┤
│ 左栏 minmax(0, 1.2fr)          │ 右栏 minmax(430px, 0.95fr)    │
│  ├ 迷宫面板  flex-1            │  ├ 决策卡          固定        │
│  │   ├ 面板头 36px             │  ├ 整局置信度图    固定 ~178px  │
│  │   ├ 屏幕井  flex-1          │  ├──────────── 分隔 ────────   │
│  │   └ 仪表条  61px            │  └ Tabs 决策历史/指标/状态       │
│  └ 操作面板  自适应高度         │      └ 唯一滚动区 flex-1        │
└───────────────────────────────┴──────────────────────────────┘
```

- **header 的内容顺序**：品牌 · **切换游戏**（图标按钮 → 弹层）· 状态胶囊 · 种子 · 时长 ·
  主操作（开始 / 恢复 / 重开）。切换游戏是**游戏页独有**的控件，导航首页没有它。
- **左栏底部的「操作面板」= `ControlBar`**：玩家 / **模型** / 速度 / 重新开始 / 更多。
  `更多` 里的内容是游戏自己的（种子、机台、本局），由各游戏的 meta 提供。
- 栅格：`grid-cols-[minmax(0,1.2fr)_minmax(430px,0.95fr)]`，`gap-4`，外边距 `p-4`。
- 固定壳生效条件：**宽 ≥ 900px 且高 ≥ 620px**。两者任一不满足时，壳退化成普通的整页滚动，
  左右两栏改为上下堆叠 —— 任何时刻**全页只有一层滚动条**。
- 高度阈值取 620 而不是整数 680：Chrome 自身要占掉约 87px，两个最常见的笔记本尺寸正好落在
  **633px（1280×720）** 与 **661px（1366×768）**。阈值定在 680 会把这两种尺寸一起推到降级分支，
  让单屏布局只剩下少数大屏用户能用到。
- 620 这个数字不是拍脑袋：右栏的固定寄存器（面板头 36 + 决策卡 277 + 分隔线 1 + 标签条 36）
  先吃掉 350px，剩下才是历史列表。620px 视口扣掉头部与内边距后仍能留出约 5 行（实测
  行高 34.4px），这是「还值得看」的下限 —— 最初按 3 行推的，实测比预期宽裕，
  所以字号再放大一档也不会掉到 3 行以下。
- 每一列内部：`flex flex-col gap-4 min-h-0`，末位面板 `flex-1 min-h-0` 吃掉剩余高度。
- 滚动容器一律加 `.scroll-area`（`overscroll-behavior: contain` + `scrollbar-gutter: stable`
  滚动条占位，避免内容增减时横向跳动）。

### 2.2 只有一层滚动条（全局不变式）

**任何尺寸下，全页有且只有一层滚动条。** 这条不变式是布局的总纲，其他规则都从它推出来：

- 壳锁定时，那一层是右栏的列表，页面自己没有滚动条；
- 壳不锁定时，那一层是页面本身，面板内部的`.scroll-area`随内容长高、不自己滚。

「一层」说的是**页面**，不是「整屏只允许一个可滚容器」。面板内部**可以同时有两个
`.scroll-area` 在滚**：右栏列表 + 展开后的「推理输入」事实表（后者自带 `max-h-[188px]`，
设计如此）。实测 1440×900（视图 813px）展开后列表仍留 ~184px ≈ 5 行，两层并存；
1280×720 展开后列表被挤成 0，只剩事实表那一个（见下面那段「已知的边界」）。
这与那条已经修掉的「双滚动条」不是一回事 —— 那个病是「**页面**在滚 + 容器在滚」。

因此**不要给滚动容器只按宽度加 `max-height` 上限**。`max-[900px]:max-h-*` 这类写法会造成
「页面在滚 + 容器在滚」的两层并存 —— 那个写法已经删掉了。原来的双滚动条不是靠隐藏滚动条解决的，
而是靠**让每个滚动容器都有确定的高度**：右栏是固定寄存器 + 一个 `flex-1` 列表，
展开「推理输入」时列表变矮，而不是页面变长。

**一个已知的边界，已决定不修**：「变矮」在矮视口上会被推到极限。视图高 ≤ 约 700px 时，
展开「推理输入」的事实表（`max-h-[188px]`，自己滚动）正好吃光右栏的剩余高度 ——
卡片是 `shrink-0`、列表是唯一的弹性项，于是列表收成 **0**，看不见、也滚不到
（面板 `overflow: hidden`）。1440×900（视图 813px）展开后列表仍留 184px ≈ 5 行，
所以只有「小屏 + 展开」付这个代价。实测与本节的字号阶梯无关：旧 11/13/15 → 卡片 468.5px、
新 12/14/16 → 472.8px、再上一档 → 477.2px，**三组列表高度都是 0**。
要改只有两条路：给列表设 3 行下限、让事实表先变矮；或把事实表在矮视口折叠进标签条
（照抄置信度图的 `CHART_STAYS_INLINE`）。两条都尚未采纳，先记在这里。

### 2.3 渲染井（画布）

每个游戏的画布（吃豆人迷宫、贪吃蛇棋盘）都装在这个井里，**井本身不带任何游戏知识** ——
它的唯一职责是把任意长宽比的画布完整地 letterbox 在可用空间里。
井（`.screen-crt`）是唯一需要缩放的盒子，它的两条网格轨道都必须是
`minmax(0, 1fr)`：

```
.screen-crt { grid-template-columns: minmax(0,1fr); grid-template-rows: minmax(0,1fr); }
```

原因值得记住：`<canvas>` 是替换元素，自带由 `width`/`height` 属性决定的长宽比。如果那一行是默认的
`auto`，画布上的 `height: 100%` 就**没有确定的轨道可以解析**，于是 `min-height: auto` 把高度交给
位图自身的比例（井是 662×320 时画布算成 662×733），再被 `overflow: hidden` 裁掉顶部和底部 ——
只剩中间 45% 的迷宫可见。

固定成 `1fr` 后轨道必定确定，`h-full` 才真的等于井高，配合 `object-contain` 把整张迷宫完整地
letterbox 在井里。**验收条件**：任意尺寸下
`画布可见高度 ÷ 画布自身高度 === 1`。

### 2.4 密度

8px 节奏（Tailwind 默认 `--spacing: 0.25rem` 正好等于原 `--s-1…--s-8`）。
面板内边距 `p-3`（12px），面板头高 36px，控制条行高 28px。
**12px 是文字下限**，只用于微标签与 num 数值（图表轴刻度 11px 是唯一例外，见 §6.5）。

### 2.5 导航首页

导航首页**不复用**锁高度的 `.app-shell`：它是目录页，不是机台。用 `min-h-dvh` 的流式壳，
但 §2.2 的不变式照旧 —— 全页**只有一层滚动条**，那一层是页面自己，页内不再放滚动容器。

```
┌──────────────────────────────────────────────────────────────┐
│ H1「游戏台」(text-kpi) · 一段说明 · 模型选择                     │
├──────────────────────────────────────────────────────────────┤
│ ┌───────────────────────────┐ ┌───────────────────────────┐  │
│ │ 游戏卡（整块 <Link>）       │ │ 游戏卡                     │  │
│ │ 名称 · 标语 · 决策形态       │ │                           │  │
│ └───────────────────────────┘ └───────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

- **整块卡可点**，不是「卡 + 卡里一个链接」；卡内三行：名称（`text-title`）、标语（`text-body`）、
  该游戏的决策形态一句话（`text-micro`）。左侧 2px 标识条用该游戏的自身色（见 §4.2），
  但**同时要有文字说明**，颜色不是唯一信号。
- 卡列表默认单列，宽 ≥900px 时两列；**不锁高、不内滚**。
- `GAME_META.length === 1` 时 `/` **直接渲染那个游戏**，不显示导航首页（多一次点击没有意义），
  游戏页头部也**不显示**「切换游戏」按钮 —— 没有可切的目标就不占 Tab 位。

## 3. 技术栈与文件地图

| 层 | 技术 | 文件 |
| --- | --- | --- |
| 设计令牌 | CSS 自定义属性 | `app/globals.css` 的 `:root` |
| 工具类 | **Tailwind v4**（`@theme inline` 把令牌映射成 `bg-panel` / `text-fg-3` / `text-micro`） | `app/globals.css`、`postcss.config.mjs` |

`components/ui/` 的 9 个原语：
`button`（primary/secondary/ghost/segmented/segmentedAccent × sm/md/icon）、`chip`（6 种语义色）、
`panel`（Panel/PanelHeader/PanelTitle/PanelActions/PanelBody/PanelScroll/PanelDivider）、
`tabs`、`switch`、`segmented`、`collapsible`、`dialog`、`tooltip`。

**目录分工**（完整版见 `docs/design-multi-game.md` §4）：
`components/ui/` 原语 · `components/charts/` 两张图 · `components/console/` **右栏（游戏无关）** ·

`lib/games/types.ts` 游戏契约 · `lib/games/registry.ts` 注册表。

**新代码一律用工具类 + 这 9 个原语**；只有画布伪元素和关键帧动画留在
`@layer components` 里（`.screen-crt`、`.attract`、`.anim-*`）。

## 4. 色彩规范

### 4.1 三层语义

```
表面   --bg-canvas → --bg-panel → --bg-elevated        （亮度分层，永不用阴影）
        --bg-inset / --bg-well                          （凹槽：表格、屏幕井）
        --bg-hover / --bg-active                        （交互态）
文字   --text-primary → secondary → tertiary → quaternary
结构   --border-subtle → standard → strong，--divider
```

`--text-quaternary` 在面板底色上不满足 AA，**仅用于不可点、次要到可忽略的数值**。

### 4.2 颜色含义是固定的

| 语义 | Token | 用在哪 |
| --- | --- | --- |
| 界面强调 / 可点击 | `--accent` `#7170ff` | 主按钮、选中态、图表主序列 |
| 已执行 / 健康 | `--status-ok` | 已执行胶囊、执行率条 |
| **本局主体 / 被选中的动作** | `--self`（每局挂一个） | 得分主读数、动作盘选中键与概率细条、概率阶梯选中行、时间线占比条、置信度图的「选项占比」序列 |
| 询问中 / 兜底 | `--status-warn` | 状态胶囊、兜底箭头与胶囊 |
| 过期 / 超时 / 错误 | `--status-bad` | 失败胶囊 |

#### 自身色 `--self` 与游戏数据色

**界面强调色永远只有靛蓝一个。** 游戏颜色一律是**数据**：只出现在画布上，以及表示「该游戏主体」的
少数读数上。为了让同一条规则在多个游戏上同时成立，引入 `--self` —— 每局在**外壳元素**上挂一个：

```tsx
<div className="app-shell" style={{ "--self": game.meta.selfColor }}>
```

上表里「本局主体」相关的每个位置都吃 `--self`，**组件里不出现任何游戏字面量**；
换游戏只换这一个变量的来源。

| 游戏 | `--self` | 取值 | 画布数据色（只进画布） |
| --- | --- | --- | --- |
| 吃豆人 | 琥珀 | `--pacman` `#ffd23f` | 迷宫蓝、豆子、四幽灵（`--ghost-*`、`--ghost-frightened`） |
| 贪吃蛇 | 绿 | `--snake-head` | `--snake-body`（蛇身）、`--snake-food`（食物） |

**颜色永远不是唯一信号**：动作盘同时用底框有无、箭头粗细、中心朝向针来表达；
状态胶囊同时写中文；导航页的游戏卡同时写游戏名与决策形态。

## 5. 字体与数字

- 字体栈 Latin 优先、简中族在日文族**之前**（`Noto Sans JP` / `Hiragino Kaku Gothic` 含汉字字形，
  排在前面会抢走中文字形）。画布 `CANVAS_FONT_STACK` 同源。
- 字号阶梯：`--fs-micro 12` / `--fs-body 14` / `--fs-title 16` / `--fs-kpi 21` / `--fs-hero 36`，
  对应工具类 `text-micro` / `text-body` / `text-title` / `text-kpi`。
  这比初版整整高一档（原为 11/13/15/19/34）—— 中文在 11px 下笔画挤在一起，13px 也偏紧。
  比值保持不变（micro/body 0.857、title/body 1.143、kpi/body 1.5），所以层次没有变，只是整体上移。
  **「把字调大」的唯一正确做法是改这五个 token**：全应用没有第二处写死字号，
  组件里也不该出现 `text-[13px]` 这类值，否则下一次调整就会漏掉它。
- **每一个数字都是 `.num`**（JetBrains Mono + `tabular-nums`）。数值每秒跳动十次，等宽字形
  是它不推挤邻居的唯一保证。
- **不用 `text-transform: uppercase`**：界面说中文，大写对 CJK 无意义，而拉丁微标签需要的大字距
  在中文里读作裂缝。需要全大写的拉丁标记（`FALLBACK`）在源码里直接写大写。

## 6. 组件规范

### 6.1 动作盘 `ActionCompass`

把「选了哪个动作」这个最核心的输出**只用一个形状表达**，而不是一句散文。

```
       ┌────┐
       │ ↑  │       有底框 + 亮箭头 = 可通行
┌────┐ ├────┤ ┌╌╌╌╌┐
│ ←  │ │ ●  │ ╎ →  ╎   暗淡无框 = 走不通
└────┘ ├────┤ └╌╌╌╌┘
       │ ↓  │       中心圆点 + 朝向针 = 主体的当前朝向
       └────┘
```

- **由 `ActionVocab` 驱动，组件不知道任何游戏**：`order` 是展示与并列时的固定次序，
  `label(action)` 是给人看的短标签（上 / 下 / 左 / 右），`slot(action)` 给四向槽位。
  `slot()` 返回 `null` 的动作**不进十字**（非四向的游戏自带动作盘，本轮未实现但接口留出）。
- 箭头图标由 `console/ActionGlyph` 按 `slot()` 统一映射到 Phosphor，
  **图标映射不进 `lib/`**（那里必须 React-free）。
- 键位 52×52，圆角 `rounded-lg`，间距 6px。
- 选中键：`var(--self)` 描边 + 同色 15% 底 + 粗体箭头（换游戏只换 `--self`，见 §4.2）；
  **兜底来的选择改画警示黄**。
- 每把键底部一条 3px 概率细条，宽度即概率 —— 不读数字也能看出分布形状。
- 交互态：有 `onPick` 时是 `<button aria-pressed>`（手动模式下即操纵键）；否则整体是
  `role="img"` + 一句话描述，**不给屏幕阅读器读一堆无意义按钮**。
- 提问期间中心点缓慢呼吸（1.6s），这是「真的在等」的诚实表达。

### 6.2 概率阶梯 `ProbabilityBars`

一行一个**合法动作**（文本取 `ActionVocab.label()`），**按概率降序**排列，并列时按
`ActionVocab.order`（形状优先于固定顺序）；选中行用 `var(--self)` 的条与字。
可点：点击即切换动作盘与「推理输入」表的高亮列，三处联动。
某次决策如果没有概率分布（例如 mock 或模型没给），**这一块显示「这次决策没有给出概率分布。」
而不是画一堆 0** —— 空值与「概率是 0」是两件事。

### 6.3 决策卡 `DecisionCard`

三档寄存器，按读者需要的顺序：**在哪**（动作盘）→ **多确定**（阶梯）→ **凭什么**（推理输入，默认折叠）。
散文放最后且最小：兜底规则、失败原因。元信息用 `dl` 收成一组 `label · value` 对
（决策点 / 决策地点 / **模型** / **来源** / 置信度 / 延迟 / 状态），
以 `flex flex-wrap` 布局横向排列，利用右侧空间、减少垂直占用。

- **「模型」与「来源」是两件事，必须分两格**：`模型` 答的是**谁**答的（渠道/模型名），
  `来源` 答的是**怎么**答的（`JEV` / `MOCK` / `RANDOM` / `HEURISTIC` / `SCRIPTED` / `FALLBACK`）。
  合成一格会让人把「兜底」读成某个模型的行为。
- 元信息的**词由游戏给**（`GameMeta` / `Question`），组件不写死游戏名词：
  同一个位置在吃豆人叫「路口」、在贪吃蛇叫「格子」。
- PENDING 状态（"答案还在路上"）不再单独显示一行文字 —— 面板头的状态胶囊已经传达了同样的信息，
  额外的段落只制造布局跳动与冗余。
- **事实表就是模型看到的东西。** 它的每一行来自 `Question.facts`，服务端送模型时用的是**同一份
  `facts`**（按 `${modelLabel}: ${value}` 拍平成 `criteria`），客户端把同一份 `facts` 渲染成表 ——
  两边不可能漂移，读者看到的正是模型看到的。表头是中文 `label`，值列对应当次的合法动作。
- 事实表（`max-h-[188px]`，自己滚动，表头 sticky）在矮视口展开时会把历史列表挤到 0 —— 这是**已知且
  接受**的行为，边界与理由见 §2.2。

### 6.4 决策历史 `DecisionTimeline`

不做「每行一句话」，做**表**：五列固定 —— 编号 / **动作** / **选项占比** / 延迟 / 状态。
动作列在四向游戏里画箭头（`ActionVocab.slot()` 有值），非四向游戏显示 `label()` 文本；
文字标签始终在 `title` 与 `sr-only` 里，颜色与箭头都不是唯一信号。
占比那一列把**条和数字合成一列**：两个表头写同一个指标会让人以为在比较两件事。
表头 sticky。悬停给 `title` 全量详情，行内再放一段 `sr-only` 说明。
兜底行在箭头与胶囊上**同时**变黄：这是唯一值得隔着一个房间也能认出来的结果。

行容器必须带 `relative`：`sr-only` 是 `position: absolute`，而行是网格 —— 少了这个定位上下文，
那段文字会掉进隐式的第二行，而它与页面之间没有任何裁剪祖先，于是跑到文档坐标里去
把 `scrollHeight` 撑大（每行约 34px），表现为一个「查不到来源」的幽灵整页滚动条。

**状态列按内容定宽（`auto`），不写像素值。** 胶囊是「一个词外面套一个盒」，盒宽随字号走：
11px 时三个汉字的胶囊是 63px，12px 时是 66px，而它当时待在一个写死的 58px 轨道里 ——
于是向左溢出 8px，正好吃掉 `gap-2` 顶到「延迟」列的数字上。这不是胶囊的错，是固定轨道与
字号脱钩。改成 `auto` 后由胶囊决定列宽，让出的空间还给唯一的弹性列「选项占比」；
以后再改字号，这一列自己就跟着走。

### 6.5 图表

- **整局置信度**（`ConfidenceChart`）：两条 area —— 「自评置信度」（靛蓝）与「选项占比」（`var(--self)`）。
  两者长期背离代表模型在犹豫。虚线均值线用于跨局比较。x 轴是**决策序号**，
  使用**固定步长**（≤40 跨度时 5、>40 时 10）与最小 20 单位的横轴域宽，
  数据少时图表左侧聚集、右侧留白，随决策增多逐渐铺满；超出窗口后丢弃左侧旧数据。
- **延迟分布**（`LatencyChart`）：**分桶边固定**（<150 / 150–300 / 300–500 / 500–800 / 800–1200 / ≥1200 ms），
  这样不同局、不同游戏之间可以比较 —— 轴会随数据移动的图表没有比较价值。
  **分桶边是 1× 速度下的参照系，不随速度动**；而「还来不来得及」的那条**截止线**是可动的：
  墙钟预算 = `budgetMs ÷ speed`（`budgetMs` 是游戏在 1× 下的可用窗口，吃豆人与贪吃蛇都取 **500 ms**，
  于是「跨游戏延迟可直接比较」这句话成立）。图上那条线的标注与「执行率」都按实际截止线判定，
  并写明当前是多少毫秒。理由见下面这条**必须同时改掉的口径**：

  > **速度会等比压缩决策窗口。** 控制器是按**游戏空间**的距离提前提问的，而速度倍率改的是游戏时钟 ——
  > 同样的距离在 0.5× 下要花两倍墙钟时间，在 2× 下只花一半。所以「速度不影响决策时限」是错的：
  > **2× 时模型只有一半的时间作答**。控件的提示文案就写这一句，不要写「速度只影响推进快慢」。
  **但它和 `stale`（`过期回答`）不是同一批记录，别混读**：直方图只看得见**测到的**延迟，
  `stale` 统计的是**所有作废的决策**。控制器会作废一批直方图根本看不见的记录 ——
  没等到答案就被丢弃的在途请求（切模式、换世代、被后面的路口取代）`latencyMs` 是 `null`，不进任何桶；
  反过来，一个按时抵达、却因为同样这些非延迟原因被作废的答案会带着很短的延迟记成 STALE，
  落进直方图眼里「完全健康」的那几桶。两者是**重叠**关系，数值不相等不代表哪一个算错了。
- 图表一律：无渐变洗色、`isAnimationActive={false}`（序列每秒增长，重播动画不可读）、
  网格只留横线、颜色取 `var(--token)`。
- **轴刻度固定 11px**（`tick={{ fontSize: 11 }}`）：它是图表家具，不是给人读的正文，
  是全应用唯一低于 §2.4 那条 12px 下限的文字。它不随 `--fs-*` 走，因为刻度是被坐标轴
  挤出来的，放大一档就得同时放宽 `YAxis width`（百分比轴 40、计数轴 34）和分桶标签的行宽。
- **`margin.left` 不要给负数。** 想靠负边距挤掉 Y 轴空白是常见写法，但轴的 `text-anchor`
  是 `end`：负的左边距把绘图区往左推，刻度文字就从画布左缘外面开始画，
  `100% / 50% / 0%` 会被裁成三个 `0%`。宁可让 `YAxis` 自己的 `width` 留够，
  再把绘图区往里收。
- 图表都是 `dynamic(..., { ssr: false })`：它是全应用唯一会拉进图表库的东西，控制台必须先画出来。
- 两张图都要 `accessibilityLayer={false}` + 容器 `role="img"` + 一句结论式的 `aria-label`，
  理由见 §8.1 —— 默认值会往 Tab 顺序里塞一个读不出名字的焦点位。

### 6.6 收敛次要内容的三件工具

| 工具 | 用来装 | 例子 |
| --- | --- | --- |
| **Tabs** | 同一位置的多个寄存器 | 决策历史 / 指标 / 状态 |
| **Collapsible** | 默认不需要、按需展开的细节 | 推理输入、操作面板「更多」 |
| **Dialog** | 散文说明，或「选一个」的短列表，完全不占版面 | 玩法与颜色说明、**切换游戏** |

规则：**默认折叠的必须是「设置一次就忘」的东西**（种子、调试、导出、音效、CRT），
或者「只在追问时才看」的东西（推理输入）。主操作、玩家选择、**模型选择**、速度永远不折叠。

### 6.7 指标口径（每个数到底在数什么）

这张面板最容易出的错不是排版，是**把「一个数」读成「一个原因」** —— 文案写成单一归因，
而代码里有好几条路径都会让它 +1。下表是唯一口径，动文案前先对着它看。

| 展示 | 字段 | 真正计入的 | 容易误读成 |
| --- | --- | --- | --- |
| 模型请求数 | `requests` | `source !== "FALLBACK"` 的记录（**含没答上来的**） | 只算成功的请求 |
| 已执行 | `applied` | `status === "APPLIED"` 且非兜底 | 所有拿到手的答案 |
| 过期回答 | `stale` | `status === "STALE"`：答晚了、切模式、换世代、被后面的决策点取代 | 只算迟到的 |
| 超时 | `timeouts` | `DECISION_TIMEOUT_MS` 内没答案、请求被彻底放弃 | 越过可用窗口的（窗口随速度变，见下） |
| 错误 | `errors` | 连接失败、模型侧报错/限流、没配 Key，**以及客户端校验没过的答案** | 只是网络问题 |
| 无效 | `invalid` | 只有 provider **不经验证**就 resolve 时才可能 —— **生产恒为 0** | 模型答得不合法 |
| 兜底次数 | `fallbacks` | `source === "FALLBACK"`：答晚了 / 没答上来 / 答得不合法**都算** | 只有答晚了 |
| 待处理 | `pending` | 还没落地的：询问中，**加上答案已到手、还没到路口的** | 只有还在等的 |

两条横贯全表的规则：

- **两个时限不是一回事，而且第一个随速度走。**
  **可用窗口 = `budgetMs ÷ speed`**：`budgetMs` 由**游戏**给，1× 下吃豆人与贪吃蛇都是 **500 ms**
  （吃豆人是 3 格 ÷ 6 格每秒，蛇是一个移动周期）。它决定答案**还能不能用**，速度越快窗口越小 ——
  **速度会等比压缩决策窗口**，2× 时模型只有一半时间作答（见 §6.5）。
  `DECISION_TIMEOUT_MS`（1500 ms）只决定**还要不要继续等**，不随速度变。
  直方图的**分桶边**固定在 1× 的参照系上（永不随速度动，这样跨局跨游戏才可比），
  那条**截止线**按 `budgetMs ÷ speed` 计算，并标注当前的实际毫秒数。
  两个数都从常量插值进文案，不要写死。
- **`无效` 恒为 0 是后果，不是 bug。** `lib/jev/validation.ts` 会先校验 decisionId、
  动作是否在本次的合法动作集内，不过就抛错，于是 `onResponse` 里那两条 `INVALID` 分支只在测试的
  `ManualProvider` 下可达；生产环境里这类回答统一记成 `错误`。要让它变活，得把
  `DecideError("invalid")` 映射成 `INVALID` 状态（会改变已有统计口径，先决定再改）。
  钉住这些行为的测试在 `tests/telemetry.test.ts` 与 `tests/jev-client.test.ts`。

#### 谁答的（模型）与怎么答的（来源）

遥测里每条记录有**两个互不相关的字段**，指标页按 `source` 计数，决策历史两列都显示：

| 字段 | 取值 | 回答 | 什么时候是空的 |
| --- | --- | --- | --- |
| `model` | 模型目录条目的 id / 显示名 | **谁**答的（哪个渠道、哪个模型名） | `null` = 这次压根没问模型（随机 / 启发式 / 录放 / 兜底） |
| `source` | `JEV` `MOCK` `RANDOM` `HEURISTIC` `SCRIPTED` `FALLBACK` | **怎么**答的 | 永不为空 |

- 「请求数」数的是**发出去的提问**，与谁答的、答没答上都无关 —— 它含没答上来的。
- **切模型即重开一局**：一局的遥测只属于一个模型，跨模型比较才有意义（决策历史里能看到每条是谁答的）。

### 6.8 仪表条 `MeterStrip`

画布下方的六格仪表。**布局是共用原语（`shell/MeterStrip`），格子里放什么由各游戏自己组装**：
标签 12px、值 16px、每局的**主读数**（吃豆人是得分，贪吃蛇是长度）用 21px 的 KPI 特例、可选附加语 12px。
**六等分是版面规则，不是内容规则** —— 每格只有 1/6 宽，所以任何「值 + 附加语」同排的格
都必须假设自己会被挤。三条实测结论：

- **格内 `px-3` 必须与面板的 `p-3` 对齐**（实测首格标签与上方面板标题的 left 差 **0.0px**）。
  宽度不够时**不要改小内边距**去腾地方：8px 能换来 4px 内容宽，代价是这条对齐变成 4px 的错位 ——
  那是拿真实的版面对齐换文案宽度。
- **附加语必须是 `flex-wrap` 容器里的 `whitespace-nowrap` 项，两条缺一不可。** 少了 `nowrap`，
  CJK 可以在任意两字之间断行，`已吃 40` 会被拆成第二行孤零零的 `40`，读起来像另一个指标
  （这就是放大字号后真出现过的样子）；少了 `flex-wrap`，就只能整格硬挤。
  两条都在时，附加语要么与值共享基线，要么**整行**降级成第二行注脚，永不半行。
- **分隔符用 4px 的 `gap-x-1`，不用 ` · `。** ` · ` 是 14.4px 的等宽空白，而它正好是 1280px 下
  「一行」与「两行」之差；换行时行首的 ` · ` 还会读成项目符号。

数值边界（1280px 视口每格内容宽 89.3px、`203` 占 28.8px）：`已吃 0`(38.4px)、`已吃 240`(52.8px)
都还在同一行，到 `已吃 2401`(60px) 才整格降为两行 —— 正常一局到不了 4 位数，所以日常不降级。
注意这一格 1280px 下原本就只有 **0.7px** 余量（旧 11/13/15 时 ` · 已吃 40` 需 88.6px），
字号整体上移一档后必然越界 —— 修的是「越界时怎么退化」，不是「怎么让它永不越界」。

**总闸门是条带的绝对宽度**，不是视口宽：最宽那格要 `值(28.8) + 4 + 附加语(52.8)` ≈ 86px 内容宽，
再加格内 25px 的 `px-3` 与分隔线 → 六格全排一行需要**条带 ≥ 约 728px**。
而条带宽度对视口**非单调**（≥900 时右栏被 `minmax(430px,0.95fr)` 顶住，视口越小条带越窄；
<900 退化成堆叠后条带又变宽），实测：

| 视口 | 条带宽 | 最宽格内容宽 | 六格 |
| --- | --- | --- | --- |
| 1920×1080 | 1042.8 | 148.8 | 一行 |
| 1600×900 | 864.2 | 119.0 | 一行 |
| 1440×900 / 1440×813 | 774.9 | 104.2 | 一行 |
| **1366×768** | **733.6** | 97.3 | 一行（连 `已吃 2401` 都是一行） |
| 1280×800 / 720 / 633 | 685.6 | 89.3 | 一行（4 位数才降级） |
| 1152 / 1024 / 960 / 900 | 614 / 543 / 480 / 420 | 71 / 66 / 55 / 45 | **早已越界**（旧字号也不够） |

所以：**1366×768 是常见尺寸里条带最宽的一档**，1280 系是临界，900 那一档是既有缺口
（要修得让六格在窄条带下改排 3×2，属版式决定，未做）。这也是为什么修法是「越界时整行降级」。

## 7. 动效规范

- 只动 `transform` / `opacity` / `background-color` / `border-color` / `width`。
- 时长：`--dur-fast 120ms`（hover、按压）/ `--dur 180ms`（进入、折叠）。
- 缓动：`--ease`（`cubic-bezier(0.2,0,0,1)`）用于交互；`--ease-out`（`cubic-bezier(0.16,1,0.3,1)`）
  用于进入。**不用回弹**：真实的东西是减速停下的。
- 按压反馈是 `scale(0.96)`，不改变布局盒。
- `prefers-reduced-motion` 在 `@layer base` 里全局接管；**没有任何信息是只靠动画传达的**。

## 8. 无障碍规范

- 语义 HTML 优先（`dl` / `table` / `ol` / `button` / `label`），ARIA 只补缺口。
- 每个图标按钮有 `aria-label`；装饰性图标 `aria-hidden`。
- 可聚焦元素统一吃全局 `:focus-visible` 光环（`--focus-ring`，靛蓝 4px 外环）。
- 动作盘用 `role="img"` + 完整句子；交互态用 `role="group"` + 每键 `aria-pressed`。
  **不可通行的动作要 `disabled`** —— 它不能执行任何动作，就不该占一个 Tab 位。
- **切换游戏与切换模型也要守同一条**：切换游戏是 Dialog（焦点交给 Dialog 原语管理），
  可切换的目标只有 1 个时按钮本身不渲染；模型选择器在非模型模式下 `disabled`，
  并在旁边用一句话说明为什么不可用。
- 决策历史每行附 `sr-only` 详情，不依赖 `title` 传达关键信息。
- 主操作按钮在 `GAME_OVER` 时 `disabled`，并提供「重开」——不给无法完成的操作留位置。
- 颜色不是唯一信号（见 §4.2）。

### 8.1 图表是「带标签的图」，不是「匿名的控件」

Recharts 的 `accessibilityLayer` 默认开启，会把画布标成
`role="application" tabindex="0"` 且**不带任何无障碍名称**。后果有两个：
它在控制台中间塞进一个焦点位，屏幕阅读器读出的是坐标轴刻度拼起来的胡话
（实测是 `1 0% 50% 100%`）；而 `role="application"` 会在获得焦点时**吞掉方向键**。

本应用的图表数据在紧邻的位置都有文字版本（历史表逐行列出每次决策的占比，
指标页有数字磁贴与计数清单），所以两张图都是：

```tsx
<div role="img" aria-label="…一句说清走势与结论的话…">
  <ResponsiveContainer>…<AreaChart accessibilityLayer={false}>…</AreaChart></ResponsiveContainer>
</div>
```

`aria-label` 要写**结论**而不是复述轴：如「…共 24 次决策；自评置信度均值 62%；最新 96%。」、
「延迟分布，共 45 次决策；最多的一档是 150–300 ms，共 21 次。」

**只有当图表是数据的唯一出口时**才反过来保留 `accessibilityLayer`，并另行补名称。

## 9. 反模式（改这个界面时不要做）

1. **不要**让页面滚动 —— 需要更多空间时，折叠或分页，不要加高。
2. **不要**在一个列里放两个滚动区。展开内容应该让列表变短。
3. **不要**把游戏配色用在界面装饰上（琥珀是吃豆人的、绿是蛇的 —— 它们只属于各自画布与自身色，不是按钮的）。
4. **不要**用阴影表达层级。层级是亮度。
5. **不要**用 12px 以下的文字（图表轴刻度是唯一例外，见 §6.5），不要给数字用非等宽字体。
6. **不要**用 emoji 当图标，不要混用图标风格（统一 Phosphor，同层级统一线宽）。
7. **不要**把动作写成散文。动作有形状，用形状；形状表达不了的动作才用词表里的短标签。
8. **不要**给高频图表加过渡动画。
9. **不要**在同一个面板里用两种时态描述同一件事（历史 vs 当前）。
10. **不要**把说明文字塞回页脚 —— 它是 Dialog。
11. **不要**让组件知道自己在跑哪个游戏。游戏差异只有三个出口：**左栏、动作词表、自身色** ——
    右栏、遥测、图表、API 必须零游戏知识。
12. **不要**让模型看到的和读者看到的来自两份数据。事实表与模型的 `criteria` 是同一个
    `facts` 对象（见 §6.3），这是「可解释」这件事的物理保证。

**布局**

- [ ] 全页无滚动：`document.scrollHeight === window.innerHeight`（宽 ≥900 且高 ≥620 时）
- [ ] **有且只有一层滚动条**：数一遍
      `[...document.querySelectorAll("*")].filter(e => e.scrollHeight > e.clientHeight + 2 && /auto|scroll/.test(getComputedStyle(e).overflowY))`
      —— 锁定时长度应为 1，降级时应为 0（那一层是页面自己）。
      **`clientHeight` 为 0 的容器要排除掉再数**：0 高的 `overflow-y: auto` 盒子同样满足判据，
      但浏览器不会给它画滚动条 —— 实测「列表被挤成 0」时该判据报 2，而可见的只有 1 条。
- [ ] **画布（迷宫 / 棋盘）不被裁切**：`画布可见高度 ÷ 画布高度 === 1`，四种尺寸都要过。
      每个游戏都要过这一条 —— 它是 §2.3 那条网格规则的验收口径。
- [ ] 开「更多」、开「推理输入」时，页面仍无滚动条。**注意这一条不是「容器数量不增加」**：
      事实表自己就是一个 `scroll-area`（`max-h-[188px]`，设计如此），展开后必然多一个满足上面
      判据的容器；矮视口下列表还会被挤成 0（见 §2.2）。**要断的是「页面」没有长出滚动条**，
      而不是「全屏只剩一个可滚容器」—— 面板内部两个 `.scroll-area` 同时可滚是预期内的。
      实测（2026-09-25，P2-7）：1440×900 展开后判据数到 **2** 个容器（列表仍留 ~184px ≈ 5 行，
      自己也在滚）；1280×720 展开后列表被挤成 0，只剩事实表 **1** 个。
- [ ] 1280×720 与 1440×900 下左右两栏都不出现横向溢出
- [ ] 1280×720（恰好压住锁定阈值）能拿到单屏布局、历史列表仍有约 5 行
- [ ] 768×900 与 1280×560 落到降级分支时，只有页面滚动、无嵌套滚动条、画布完整
- [ ] **导航首页**（游戏 ≥2 个时）：`/` 是导航页、只有一层滚动条且那一层是**页面自己**、
      每张卡可进对应游戏、卡上的游戏名与决策形态是可读文字而不是只靠颜色
- [ ] 帮助弹层打开时根滚动被锁：`html` 的 `overflowY` 为 `hidden`，`innerWidth - clientWidth === 0`

**功能**

- [ ] 每个游戏页都能：开始 / 暂停 / 重开 / 切玩家 / 切模型 / 开「更多」/ 开「推理输入」/
      开调试 / 导出 JSON，且控制台无报错（尤其 Radix ref 转发与控制件嵌套）
- [ ] **切换游戏**弹层：列出全部游戏、当前项有标注、能返回导航首页；
      `GAME_META.length === 1` 时头部不渲染这个按钮
- [ ] **切换模型即重开一局**，且决策历史里每条记录都能看出**是哪个模型答的**（模型 · 来源两格）
- [ ] 把模型目录配成两条（其中一条故意不给 Key）：选择器显示两条、未配 Key 的那条有明确标注、
      选中时报「未配置 API Key」、**页面上任何位置都看不到 Key 或 baseURL**
- [ ] **事实表 = 模型看到的**：展开「推理输入」，表的行与本次请求送出的 `criteria` 逐行一致
- [ ] **延迟图的截止线**随速度变（`budgetMs ÷ speed`，标注写明毫秒数），**分桶边不变**
- [ ] 导出的 JSON 含 `game` 与 `model`

**无障碍与动效**

- [ ] Tab 标签页要用**真实指针事件**切换 —— Radix 在 `pointerdown` 上切，合成 `click()` 无效
- [ ] **键盘顺序**：`document.querySelectorAll` 里的可聚焦元素顺序应为
      跳转链接 → 头部主操作 → **切换游戏** → 画布面板的说明按钮 → 玩家 → **模型** → 速度 →
      重新开始 → 更多 →（有决策时）动作盘的可通行键 → 概率阶梯行 → 推理输入 → 标签条 → 标签页。
      可用 `checkVisibility()` 过滤掉折叠内容与未激活标签页里的元素后逐项打印核对；
      `positiveTabindex` 必须为空数组（有正值就会打乱 DOM 顺序即 Tab 顺序的前提）。
      **不要为了「有焦点」而给不可操作的东西留 Tab 位**：不可通行的动作是 `disabled`，
      图表是 `role="img"`（见 §8.1），非模型模式下的模型选择器也是 `disabled`。
- [ ] **`prefers-reduced-motion`**：用 `--force-prefers-reduced-motion` 起 Chrome，
      断言 `document.getAnimations().filter(a => a.playState === "running").length === 0`，
      且**信息不丢**（画布提示语、仪表条标签、决策面板文字仍在），对局仍能正常推进。
- [ ] `matchMedia("(prefers-reduced-motion: reduce)")` 生效后没有元素靠动画才能读到状态。

实测建议跑 `npm run dev` 而不是 `npm start`：改完文案/样式秒级生效，省掉每轮几十秒的构建。
浏览器侧走 `@skill:web-access` 的 CDP 代理（`/new`、`/eval`、`/clickAt`、`/screenshot`）即可，
但有三个必须记住的坑：

1. **改完 CSS/组件要先 `Page.reload` 再量数据** —— HMR 对本项目的这类改动是滞后的，
   立刻量到的是旧 bundle，会把「已修好」误判成「修了没用」。
2. **新开的标签页在后台，游戏循环会正确地暂停**（`document.hidden`）——
   必须先关掉其它标签页把它置前，否则会误判成「对局没跑起来」。
3. **Radix 系控件在 `pointerdown` 上切换**，必须发真实指针事件。
